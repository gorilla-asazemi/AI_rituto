# 『＠ゴリーダー元素』Webサイト開発 設計書（シンプルHTML版）

**作成日**: 2026-08-22  
**開発方針**: Viteや複雑なDBを使わず、HTML/CSS/JavaScriptだけで初心者でも直感的に作れて壊れにくい「最小にして最強の構成（MVP）」で構築する。

- **サイト名**: **『＠ゴリーダー元素』**
- **キャッチコピー**: 「静かな森の美術館で味わう、純度100%の一行格言」
- **コンセプト**: **「あたたかくて静かな、ジャングルの美術館」**
- **ゴール**: 
  - **最優先ゴール**: Kindle書籍の購入（各所からの自然な誘導）
  - **体験ゴール**: クスッと笑えて共感できる格言・プチ解説を浴びる体験
  - **拡散ゴール**: X（Twitter）への引用シェア

## 2. ターゲット・ペルソナ
- 広く一般の会社員・ビジネスパーソン
- 人前で話す機会のあるスピーカー・講師・リーダー層
- 「正論」や「型」に少し疲れ気味の頑固な人・こだわり派

## 3. 第1フェーズ（MVP）で実装する「厳選5大機能」
初心者でも確実に動かせ、サーバー費用もかからない構成に厳選：

1. **ジャングルの美術館デザイン（完全レスポンシブ）**
   - 深い森のダークグリーン壁面 ＋ 和紙アイボリーの額縁カード
   - スマホ・PCどちらでも美しく見やすいグリッド／縦並びレイアウト
2. **カードのフリップ（裏返し）演出**
   - カードをクリック／タップすると滑らかに裏返り、**「100〜150文字のプチ解説」**が出現
3. **お気に入り（保存）機能**
   - 読者が気に入った格言をワンタップで保存（ブラウザのローカルストレージ活用・DB不要）
   - 「保存した格言だけ見る」絞り込みボタン
4. **X（Twitter）シェアボタン**
   - カード裏面のボタンを押すと、その格言とURLがセットされた投稿画面が即座に開く
5. **Kindle導線（CTA）**
   - ヘッダー、カード裏面、フッターに配置し、いつでもKindle本へ移動可能

## 4. ファイル構成（超シンプル設計）
難しいビルドツールは使わず、フォルダを開いてブラウザでダブルクリックするだけで動く構成：

```text
/（プロジェクトフォルダ）
├── index.html       # サイトの骨組み（ヘッダー・ギャラリー・フッター）
├── style.css        # デザイン・色・カード裏返しのCSSアニメーション
├── script.js        # カードフリップ、お気に入り保存、Xシェアの動作
├── data.js          # 格言・解説・画像パスのデータ置き場（更新はここだけ）
└── images/          # 格言画像ファイル
    ├── 260821_talk.jpg
    ├── 260822_listen.jpg
    └── 260823_tobacco.jpg
```

## 5. 日々の更新フロー（超かんたん方式）
管理画面などの複雑なシステムを作らず、`data.js` に以下のように**1行コピペして追加するだけ**で新しい格言がサイトの一番上に自動反映されます。

```javascript
// data.js のイメージ
const sayings = [
  {
    id: "004",
    date: "2026-08-23",
    title: "「嫌い」を主張して手に入れたのは、個性やなくて孤立やった",
    explanation: "尖るのと孤立するのをごっちゃにしてた黒歴史。自分の意見を持つのはええけど、ただの拒絶は誰も寄り付かんようになるだけやったなぁ…",
    image: "images/260823_hate.jpg"
  },
  // ...新しい投稿を上に追加していくだけ
];
```

## 8. 初心者でも安全に公開できる「セキュリティ設計」
HTMLサイトをネット上に公開する際、トラブルや情報漏洩を未然に防ぐための必須ルール：

### 1. APIキー・秘密情報の露出ゼロ原則
- **ブラウザから見える場所に秘密情報を置かない**: 
  - HTMLやJavaScriptに書いた内容は、誰でも「ページのソースを表示」で閲覧できます。
  - **有料APIの秘密鍵（Secret Key）、管理者パスワード、個人情報**はコード内に絶対に直接書かない（ハードコード禁止）。
- **外部APIやDBを使う場合の安全設計**:
  - 第1フェーズではAPI不要の完全静的設計を採用（リスクそのものをゼロにする）。
  - 将来外部サービスを導入する場合も、環境変数（`.env`）の利用や、公開用キー＋アクセス権限制御（Row Level Security等）を徹底する。

### 2. 静的サイト（HTML/CSS/JS）による根本的安全性の確保
- サーバー側でプログラムを動かさない「静的ホスティング（GitHub Pages / Cloudflare Pages等）」を採用。
- これにより、**サーバー乗っ取り、DB流出、SQLインジェクションなどの致命的な攻撃リスクを根本から排除**。

### 3. XSS（クロスサイトスクリプティング）防止
- 将来コメント入力や動的テキスト表示を行う際、悪意あるスクリプトが実行されないよう、`innerHTML` ではなく安全な `textContent` によるテキスト描画を徹底する。

### 4. 外部リンクの安全対策
- Amazon（Kindle）やX（Twitter）などの外部リンクには、必ず `target="_blank" rel="noopener noreferrer"` を設定し、別タブ経由のセキュリティリスク（タブ乗っ取り等）を防ぐ。

### 5. GitHub等への誤公開防止
- Git管理を行う場合は `.gitignore` を設定し、意図しない設定ファイルや個人用メモがネット上に流出するのを防ぐ。
